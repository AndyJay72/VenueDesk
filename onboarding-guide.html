Logging In

Copy link

The dashboard is protected by an admin key gate — not the same as the staff JWT login used by venue managers.

  • 1
    Navigate to the dashboard URLThe login card appears over a dark background — the main app is hidden until authenticated.
  • 2
    Enter the Admin KeyType the key into the password field. Press Enter or click Access Dashboard.
  • 3
    Dashboard loadsVenues load, the telemetry panel fires its first latency ping, and the DB health dot turns green.
Session expires on browser close. The admin key is stored in sessionStorage only — there is no "stay logged in" option. Re-enter the key each new session.

Onboarding a New Venue

Copy link

The left-hand Onboard New Venue form creates a complete venue account — database record, tenant isolation, and staff login credentials — in a single operation.

Editing a Venue

Copy link

Click the Edit button on any table row (or Edit Details inside the Venue Detail Panel) to open the Edit Venue modal.

FieldNotes
Venue NameUpdates the display name everywhere in the platform.
SlugAuto-updates as you type the name. Only change manually if you need a specific URL key.
Contact NameUpdates the staff display name shown in the venue's dashboard sidebar.
Staff SeatsAdjust seat allocation up or down. Pricing preview updates in real time. The new value is saved to the database.

Password Management

Copy link

Reset Password (existing user)

Use when a venue manager is locked out or requests a new password.

  1. 1
    Click 🔑 on the table rowModal shows the existing username (read-only).
  2. 2
    Enter new password (min 6 chars)
  3. 3
    Click Reset Password

Set Login (new user on existing venue)

Use when a venue was created without a username, or needs a second account.

  1. 1
    Click 🔑 on a row with no usernameModal shows a Username input field.
  2. 2
    Enter username and password
  3. 3
    Click Set LoginA new staff user account is created for this tenant.
Passwords are hashed with SHA-512 + a server-side pepper before storage. There is no way to recover a lost password — only reset it. Always communicate new passwords to venues through a secure channel.

Activating & Deactivating Venues

Copy link

Click the ⏸ Pause button to deactivate, or ▶ Play to reactivate. A confirmation prompt appears before any change is applied.

State changeWhat happens
Active → InactiveVenue's booking form rejects new enquiries. Staff can still log in. Row badge turns grey.
Inactive → ActiveReverses the above immediately. Enquiries accepted again.
Deactivation is soft — no data is deleted. The venue's bookings, customers, and history remain intact. This is the correct action for a payment dispute or subscription lapse; use it before considering any data deletion.
Every toggle action is automatically written to the System Audit Log with a timestamp and the target tenant ID.

Create a booking on behalf of this venue without going through the enquiry form.

Connected tabs are live sessions. Any action you take (create a booking, edit a customer, record a payment) affects real data permanently. Always close the venue tab when you are done to avoid accidental changes.

Copying the Public Enquiry Link

Copy link

Every venue has a unique public-facing booking enquiry form URL. Click the 🔗 Enquiry Link button on any table row to copy it to your clipboard.

Share this URL with the venue so they can embed it on their website or include it in marketing. The URL format is:

https://andyjay72.github.io/VenueDesk/enquiry-form.html?t=1001

The ?t= parameter is the venue's tenant ID. Enquiries submitted through this form are routed directly to that venue's dashboard under Pending Requests.

If the clipboard copy fails (older browsers), a toast notification shows the full URL so you can copy it manually.
If you change a venue's slug in the Edit modal, existing enquiry links using the old slug will break. Always redistribute a new link after a slug change.

Session & Security Notes

Copy link
  • Session expires on browser closevd_admin_auth is stored in sessionStorage only. There is no "stay logged in" — every new browser session requires re-entering the admin key.
  • Admin key visible in page sourceThe dashboard is for internal admin use only. Do not share the URL publicly. The admin key is embedded in the JS for operational convenience — treat it as sensitive.
  • Every admin action is loggedCreate, reset-password, and toggle-venue operations write an audit record automatically. No manual step required.
  • Connected venue tabs are liveImpersonating a venue opens a real session. Bookings, payments, and edits made there are permanent. Close the tab when done.
  • Latency checks send no credentialsThe 30-second ping to /health/ping is an unauthenticated GET. No session data, tenant data, or admin key is transmitted.

Glossary

Copy link
Tenant

A single venue account on the VenueDesk platform. Each tenant has a unique tenant ID, its own isolated database records, and its own staff login credentials.

Tenant ID

A unique integer (≥ 1000) that identifies a venue throughout the platform. Appears in booking URLs as ?t=1001. Never reuse a retired ID.

Slug

A URL-safe version of the venue name, e.g. the-park-suite. Used in the public enquiry form link. Lowercase letters, numbers, and hyphens only.

Seat / max_users

The number of staff login accounts a venue is licensed to have. One is included in the base subscription; additional seats are £5/month each.

Admin key

The master password that gates access to this onboarding dashboard. Separate from the venue staff JWT login. Stored only for the current browser session.

DB Health dot

The coloured pulsing circle in the telemetry panel. Green = last venue data load succeeded. Red = last load failed, possible API or database issue.

API Latency

Round-trip time in milliseconds from your browser to api.venuedesk.co.uk. Under 300 ms is normal; over 800 ms warrants investigation.

Impersonate / Connect

Opening a venue's dashboard in a new tab pre-authenticated as that tenant's admin. Used for support and setup. All actions in that tab are real and permanent.

Subscription status

The billing state of a venue: Active (paid), Trial (free period), Past Due (payment overdue). Driven by the subscription_status field in the database.

Audit log

A timestamped record of every admin write operation. Stored in the database and accessible via the System Audit modal. Cannot be edited or deleted from the UI.

Health pulse

An automated background check that runs every 5 minutes via a scheduled workflow. Sends a POST to /health/pulse so the API can record system telemetry.

Enquiry link

The public-facing URL for a venue's booking form. Format: enquiry-form.html?t=<tenant_id>. Enquiries submitted here appear in the venue's Pending Requests list.
